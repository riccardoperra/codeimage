# Local AI

A request in plain words, such as "add a tab with this code `…`, use Dracula, padding 32, export PNG 2x", becomes editor changes. Chrome's on-device model (Prompt API, Gemini Nano) plans the change, and the page runs the plan through the same tools that browser agents call. Nothing leaves the browser and there is no cloud fallback.

## Sub-features

The experiment switch, the on-device model row under it, the command, the dialog with its request field, Run, and one row per step with its tool and `Done` or the tool's error. Fenced code blocks never reach the model: the page swaps them for `CODE_1`, `CODE_2` and puts the code back when a step names one. The model answers with `{steps: [{tool, args}]}` under a JSON Schema `responseConstraint` that lists only the tools that act. The plan stops at the first step that fails. A new session opens for each request, with a system prompt that lists the tools, every theme name, the featured languages, the tabs and each setting with its valid values.

## How to get to it (user POV)

Only in a browser that exposes `LanguageModel`; without it the Local AI group is hidden. Settings → Experiments → Local AI → Use local AI. The On-device model row under the switch says where the model stands: ready, needs a download (Download model), downloading with a progress bar (indeterminate with `Downloading… Chrome doesn't report progress yet.` and a copy chip for chrome://on-device-internals, which shows the live download status, until Chrome reports progress above 0, then the bar and a percentage), cannot run here (`Chrome says it cannot run on this device.`) with Check again, or failed with the error and Retry. While the model is unavailable, downloadable or failed, the row lists Chrome's requirements (Chrome 148+ on desktop; Windows 10/11, macOS 13+, Linux or ChromeOS on a Chromebook Plus; more than 4 GB of VRAM or 16 GB of RAM; 4+ cores; about 20 GB free; On-device AI on), each marked met, not met or check yourself from what the page can read (`userAgentData` high-entropy hints, `hardwareConcurrency`, `deviceMemory`, which Chrome caps at 8 and which never decides memory alone, since a GPU with more than 4 GB of VRAM also qualifies; disk space, VRAM and the Chrome setting are never readable), and two copy chips for chrome://settings/ai and chrome://on-device-internals, since a page cannot open chrome:// addresses. `local-ai/requirements.ts` holds the rules, with unit tests. The switch stays off and disabled until the model is available. The page asks `availability()` on load and on each visit to Experiments, polls it every 5 s while a download runs, and never calls `create()` when it answers `unavailable`. Only the Download model click, or the dialog when the model is already `available`, calls `create()`. The command menu (Cmd/Ctrl+K) offers Ask local AI… only once the model is available and the experiment is on, on an editable snippet only. The dialog never downloads: if the model is not available it says so and links to Experiments.

## Driving it with Playwright

`VERIFY_AUDIT=1 VERIFY_CASES=local-ai node .agents/skills/verify-codeimage/scripts/verify.mjs`

The case runs three fresh Inspector contexts whose init script installs a fake `LanguageModel`. In the first it starts `downloadable`, records the system prompt and each prompt, and answers two canned requests with canned plans. The case checks that the command is absent before the experiment, opens Settings → Experiments and clicks Download model. The fake reports progress 0, then 0.5 1.5 s later, then resolves: `create()` must not have run before the click; the row must list six requirements before the click, then show an indeterminate bar with `Downloading… Chrome doesn't report progress yet.`, no requirements and only the chrome://on-device-internals chip, then a bar at 0.5 with `50%` and no chip, then `Ready on this device.` with no button. It turns the switch on, opens the command from the menu and types the request with a fenced Python block. Run must show four `Done` rows: `add_tab` with `CODE_1`, `apply_theme`, `set_controls` with `frame.padding` 32 and `export_image` PNG at 2x. It asserts that the prompt carries `CODE_1` and the fence hint but not the code, that the schema enum excludes `get_editor_state`, and that the system prompt stays under 12,000 characters. After the dialog closes, CodeMirror must show the code, the window `hello.py`, the theme list Dracula and the frame a new padding. The downloaded PNG must be the live frame at 2x. A second request whose plan applies an unknown theme must leave one failed row and download nothing. The second context loads while `availability()` already says `downloading` and flips to `available` 8 s after load with no progress events: the row shows an indeterminate bar with the switch disabled, and a poll (not the visit) must bring `Ready on this device.`; the case then turns the switch on and the command shows. The case opens the dialog, makes the fake answer `downloadable`, and presses Run: the dialog must say the model is not ready, Open experiments must land on the Download model button, and the fake's `create()` must never have run in this context. The third context's init script also fixes `hardwareConcurrency` at 8 and `deviceMemory` at 4, and its `create()` rejects: the row must show `The download failed (Not enough disk space).` with Retry; once the fake answers `unavailable`, reopening Experiments must say Chrome cannot run it, with a disabled switch, a Check again button, and the requirements with the cpu met, and memory (shown as 4 GB, so it needs the GPU), disk and setting to check; the chrome://on-device-internals chip's Copy must turn to Copied and put the address on the clipboard. Evidence lands in `local-ai-2x.png`, `local-ai-dialog.png`, `local-ai-row-{downloadable,downloading-indeterminate,downloading,ready,failed,unavailable}.png` and the `local-ai*-trace.zip` files.

Source: `pages/UnifiedEditor/local-ai/` (`plan.ts` holds the code-block extraction, plan schema, plan parsing, `runPlan` and the prompts, with unit tests; `language-model.ts` the Prompt API boundary and the shared model state, with unit tests; `LocalAi.tsx` the dialog), `shell/sections.tsx` for the Experiments rows, `shell/preferences.ts` for the `localAi` experiment and `agent-tools/tools.ts` for the tools.

## Gotchas

The fake model proves the wiring, the prompt contents and the effects, not the quality of Gemini Nano's plans. A real run needs Chrome with the on-device model available, which a fresh Playwright profile reports as `unavailable`. The audit measured a 3,078-character system prompt for the default editor; keep it well under the model's input quota when adding tools or settings. The model may still name a theme or value the tools reject: the failing step's row shows the tool's error.
