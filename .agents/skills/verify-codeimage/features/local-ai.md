# Local AI

A request in plain words, such as "add a tab test.tsx with this code …, use Dracula, padding 32, export PNG 2x", becomes editor changes. Chrome's on-device model (Prompt API, Gemini Nano) calls the editor's agent tools natively, and the page runs each call through the same registry that browser agents use. Nothing leaves the browser and there is no cloud fallback.

## Sub-features

The experiment switch, the on-device model row under it, the Ask AI button in each desktop layout's action bar, the command, and the inline bar that takes the action bar's place: a request field (Enter sends, Shift+Enter breaks the line, Esc closes and gives the focus back to Ask AI), Send and Close. Above the bar, a list shows the request, Thinking… while the model works, the model's own words before a call, each call as running then done or failed with its localized title, the raw tool name, an argument summary and the tool's error, then the model's answer. A run stops after 6 turns of calls and says so. A new request clears the list. The floating agent activity card does not repeat these calls. No Ask AI on a phone (768 px and narrower): no button, no command, no bar.

`model.ts` is the model-agnostic API (`ModelProvider.open({system, tools, history, signal})`, `ModelSession.stream(input)` yielding `text-delta`, `tool-call` and `done` events). `agent.ts` holds the loop as a reducer over a `Run` (phase, entries, text): it reads `get_editor_state` itself and passes it as history, opens a session with the 8 tools, runs each call, sends the results back and continues until the model stops or 6 turns pass. `chrome-provider.ts` is the only code that knows the Prompt API: one base session per system prompt and tools, cloned for each request, the state appended as an assistant tool call and its `LanguageModelToolSuccess`, `promptStreaming()` for every turn (text chunks taken as deltas or as the text so far), `LanguageModelToolSuccess`/`LanguageModelToolError` for results, and `[local-ai]` console logs of each step. A rejected `create()` reads as `Chrome could not start the on-device model. Check free disk space and chrome://on-device-internals.` (InvalidStateError) or `Chrome's on-device model can't run tools in this browser.` (anything else), with the raw error in the console.

## How to get to it (user POV)

Only in a browser that exposes `LanguageModel`; without it the Local AI group is hidden. Settings → Experiments → Local AI → Use local AI. The On-device model row under the switch says where the model stands: ready, needs a download (Download model), downloading with a progress bar (indeterminate with `Downloading… Chrome doesn't report progress yet.` and a copy chip for chrome://on-device-internals, which shows the live download status, until Chrome reports progress above 0, then the bar and a percentage), cannot run here (`Chrome says it cannot run on this device.`) with Check again, or failed with the error and Retry. A download Chrome reports without progress, and that this page did not start, offers Restart download, which calls `create()` again from the click. While the model is unavailable, downloadable or failed, the row lists Chrome's requirements (Chrome 148+ on desktop; Windows 10/11, macOS 13+, Linux or ChromeOS on a Chromebook Plus; more than 4 GB of VRAM or 16 GB of RAM; 4+ cores; about 20 GB free; On-device AI on), each marked met, not met or check yourself from what the page can read (`userAgentData` high-entropy hints, `hardwareConcurrency`, `deviceMemory`, which Chrome caps at 8 and which never decides memory alone, since a GPU with more than 4 GB of VRAM also qualifies; disk space, VRAM and the Chrome setting are never readable), and two copy chips for chrome://settings/ai and chrome://on-device-internals, since a page cannot open chrome:// addresses. `local-ai/requirements.ts` holds the rules, with unit tests. The switch stays off and disabled until the model is available. The page asks `availability()` on load and on each visit to Experiments, polls it every 5 s while a download runs, and never calls `create()` when it answers `unavailable`. Only the Download model click, or a request when the model is already `available`, calls `create()`. Ask AI and the command menu's Ask local AI… show only once the model is available and the experiment is on, on an editable snippet, on a computer. The bar never downloads: if the model is not available it says so and links to Experiments.

## Driving it with Playwright

`VERIFY_AUDIT=1 VERIFY_CASES=local-ai node .agents/skills/verify-codeimage/scripts/verify.mjs`

Every context installs a fake `LanguageModel` with `clone()`, `append()` and `promptStreaming()`, plus fake `LanguageModelToolCall`, `LanguageModelToolSuccess` and `LanguageModelToolError` classes, by init script. It streams scripted chunks per request: text (the second chunk repeats the first, as cumulative text would), then `tool-call` parts, and records the base sessions, clones, appended history and every prompt.

The first Inspector context downloads the model from Experiments (progress 0, then 0.5, then ready, with the requirement list and chips as before), turns the switch on, opens the bar from Ask AI and checks focus, Shift+Enter and that the field keeps its keys. The canned request must show thinking, each of `add_tab`, `apply_theme`, `set_controls` and `export_image` running then done with its summary, the model's note once, and the answer; CodeMirror shows the code in a new `test.tsx` tab, the theme is Dracula, the padding changed and the downloaded PNG is the frame at 2x. The fake must have one base session with the 8 tools, no editor state in its system prompt, a history append whose `get_editor_state` call and success share a callId and carry the real state, and tool responses carrying `call-1` to `call-4`. A second request applies the theme Nope: its row fails, the `LanguageModelToolError` sent back carries `bad-1` and the error, the answer shows, and the base session was created once and cloned twice. A third request calls a tool every turn and must stop at 6 rows with `Stopped after 6 turns`. Esc closes and focuses Ask AI; the command reopens an empty bar with the field focused.

The second context loads while Chrome downloads and becomes available by polling. Its fake then rejects `create()` with InvalidStateError: the bar must show the disk-space message. Then it answers `downloadable`: the bar must say the model is not ready and Open experiments must land on Download model. The third context covers the failed download and the unavailable requirements as before.

Three more contexts open the bar in Inspector, Dock and Studio at 1440 px: the frame must not move, the bar must stay on screen with no horizontal scroll, and the list must sit above the bar. Three phone contexts at 390 px assert that neither Ask AI nor the command exists. Evidence: `local-ai-{inspector,dock,studio}-{idle,thinking,running,done}.png`, `local-ai-answered.png`, `local-ai-failed.png`, `local-ai-turn-limit.png`, `local-ai-2x.png`, the `local-ai-row-*.png` files and the traces.

Source: `pages/UnifiedEditor/local-ai/` (`model.ts`, `agent.ts`, `chrome-provider.ts` and `language-model.ts` with unit tests; `LocalAi.tsx` the button, the bar and the list), `agent-tools/ToolActivity.tsx` for the shared `ToolRow`, `controls/CanvasToolbar.tsx` where the bar replaces the action bar, `shell/sections.tsx` for the Experiments rows and `agent-tools/tools.ts` for the tools.

## Gotchas

The fake model proves the wiring, the Prompt API message shapes and the effects, not Gemini Nano's choices. The explainer does not say whether `promptStreaming()` yields tool-call parts or whether text chunks are deltas; the `[local-ai]` console lines show the real chunks. A fresh Playwright profile reports the model as `downloadable`, so a real run needs the maintainer's Chrome. The seeded editor state measured about 7,200 characters for the default editor, which counts against Nano's context on every request. The What's new Nudge can announce in the moment between closing Settings and opening the bar; the audit dismisses it.
